# Code of conduct

## The short version

Be decent. Assume the other person is trying. If someone is not, tell a
maintainer rather than the thread.

That is the whole rule, and for almost everyone it is the whole document. The
rest of this page exists so that nobody has to guess what happens in the cases
where the short version is not enough.

## What we expect

- **Argue about the work, not the person.** "This breaks determinism on
  Windows, here is the failing hash" is a good comment. "This is amateur work"
  is not, and it is also less useful.
- **Take correction plainly.** Everyone here has shipped a bug. A maintainer
  saying your patch is wrong is not a verdict on you.
- **Leave people room to be new.** Orbital mechanics, fixed-point determinism
  and GDScript's type inference are each a lot to hold at once. Someone asking
  an obvious question is someone learning in public, which is a thing worth
  having.
- **Respect a "no".** A maintainer declining a feature is an answer, not the
  opening of a negotiation. [CONTRIBUTING.md](CONTRIBUTING.md) lists the things
  this project will say no to, so most of these answers are predictable in
  advance.

## What is not acceptable

Harassment in any form; slurs or demeaning comments about anyone's identity;
sexual attention or imagery in project spaces; publishing anyone's private
information; sustained disruption of discussion; and threats or encouragement
of self-harm or violence.

Deliberately wasting maintainer time also counts — reopening a settled
argument, filing the same rejected patch again under a new title, or
submitting code you did not write and cannot explain.

## Where this applies

Issues, pull requests, commit messages, code comments, discussions, and
anywhere someone is representing the project.

## Reporting

Open a **private vulnerability-style report** via the repository's Security tab
if the matter is sensitive, or contact a maintainer directly through their
GitHub profile. If a maintainer is the problem, contact a different one.

Reports stay between you and the maintainers handling them. You will not be
asked to confront the other party, and you will not be told to "work it out".

## What happens next

In order, and skipping straight to the end for anything severe:

1. A private word, saying which behaviour and why.
2. A public correction in the thread.
3. A temporary block from interacting with the repository.
4. A permanent ban.

The reasoning gets recorded even when the decision is not public, so that a
later maintainer can see what was decided and why.
